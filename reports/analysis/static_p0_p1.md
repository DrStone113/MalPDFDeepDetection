## Feature groups and reference contract

The compatible candidate group reuses `static.schema.RIT_FEATURES` and
`static.raw_scan` / `static.rit_reference`, with PDFMalExtract v0.1 pinned to
[`1aaba0896ae395ddadbf1010ab9e887eedc38ea1`](https://github.com/Mo-Alani/PDFMalExtract/blob/1aaba0896ae395ddadbf1010ab9e887eedc38ea1/PDFMalExtract.py)
and PyMuPDF 1.26.7. The run's `feature_definitions.csv` enumerates every predictor,
method, unit, source and failure convention using the existing coverage builder.
Verified source definitions are not record-level proof of equality to the
publisher's original CSV generation environment.

| Feature group | Measurement / unit | Failure convention and limitation |
| --- | --- | --- |
| `pdfsize` | `int(file_bytes / 1000)`, decimal kB | Null if the reference contract cannot run; byte length is separate metadata |
| Metadata / title | UTF-8 bytes of `str(document.metadata)` / Python characters | Null on unavailable metadata; not arbitrary serialized object size |
| Pages / xref | PyMuPDF page count / `xref_length()` | Original source-returned zero differs from null; caps produce explicit issues |
| `isEncrypted` | `int(bool(metadata['encryption']))` | pypdf's encryption flag remains a separate diagnostic; passwords are never attempted |
| Images | Sum of per-page `get_images()` reference counts | Source `-1` on loop failure; shared images can count on multiple pages |
| `contains_text` | Aggregate extracted text strictly **greater than 50** characters | Source `-1` on outer-loop failure; individual page failures are counted separately |
| Embedded files | PyMuPDF `embfile_count()` | Published outer-loop failure uses zero plus an explicit warning; this legacy sentinel must not mean absence in an advanced model |
| PDF version | `float(metadata['format'][4:7])` | Null on failed conversion; source values are not clipped |
| 31 lexical counters | Exact byte occurrences and released overlap subtractions | Completed byte scanning supports zero; these are not action/object totals; retain `/Acroform`, `j/BaseEncoding` and `/ObjStm` source conventions |
| CIC advanced evidence | Parsed structural observations, JS extraction/AST and coverage | Unknown totals are null, measured partial evidence is separate; no AST/Markov vector can be obtained from RIT CSV |

The new diagnostic fields are supplemental CIC candidates. They are not joined
to RIT as all-zero columns and are not predictors in existing frozen models.
The historical strict-six study concerns original CIC table fields; it does not
verify all 41 measurements from the raw-PDF extractor by matching column names.
Identifiers, paths, hashes, dataset/source and labels are audit fields.

The [RIT authors](https://github.com/Mo-Alani/RIT-PDFMal-2026) distinguish malicious
VirusTotal collection (2017–2025) from crawler-collected benign PDFs. The
[CIC description](https://www.unb.ca/cic/datasets/pdfmal-2022.html) describes
cluster-based evasive selection; it does not establish that every local mirror
row is near a classifier decision boundary.

## Confirmed gaps and corrections

| Existing location | Confirmed issue | Correction / evidence |
| --- | --- | --- |
| `pdf_parser._StructureWalker.walk` | Failed indirect resolution was silently skipped; initialized zeros could survive parser failure, encryption or incomplete traversal | Unknown totals stay null; `structural_complete` and observed lower bounds are explicit; recognize standard `/AcroForm` without changing RIT lexical spelling |
| `code_inspector._inspect_code_bytes` | Failed JS decoding/AST returned zero AST summaries; unresolved objects could erase all results in the outer worker exception path | Continue resolvable siblings, null incomplete aggregates, preserve observed evidence and per-script object/path/extraction/AST status |
| `inference.predictor.StaticScanSession._batch` | Numeric compatibility alone could admit a failed parser result | Parsing completeness/resource/fatal-error checks precede model loading and prediction |
| `code_inspector.inspect_pdf_codes` | Cleanup killed only the direct worker | Disposable process groups and group kill; synthetic timeout test covers descendants; one-worker default |
| `coverage._method_for` | `isEncrypted` documentation attributed the canonical feature to pypdf | Correct attribution to the existing PyMuPDF source method |
| Protocol P/G runner tests | Temporary fixtures inside the worktree inherited the parent repository's Git state | Isolate synthetic Git metadata explicitly; production clean-worktree checks remain in force |

The generated fixture tests exercise JS strings, hex strings, indirect values
and streams in document/page/annotation/form actions, name trees, cyclic `/Next`,
and an action inside an object stream addressed by an xref stream. Existing
bounded Flate, unsupported-filter, decode-parameter, malformed syntax and
snapshot-change checks remain in force. No JavaScript runtime is invoked.

Output contracts are now `static-diagnostics-v2` and `pdf-code-inspection-v2`.
Canonical RIT input order and raw feature values retain their original
definitions. The JSON fields `ast` / structural totals can now be null where v1
reported misleading zeros; consumers must check completeness. `observed` values
are lower bounds, not valid substitutes for totals. Source paths are bounded,
fixed PDF vocabulary with unknown keys redacted; they describe the first
encountered occurrence, not all graph edges or execution triggers.

There is no persistent cache of structural/AST evidence in the current code.
Old diagnostic JSON must be recomputed and cannot be promoted to v2 by changing
its version string. `cache_manager` stores checksum-verified byte Markov matrices;
their bytes and algorithm are unchanged by this maintenance. Future JS caches
need PDF identity, this schema version, backend versions and effective limits in
their keys, and must not reuse partial results as completed extraction.

## Resource boundary and remaining work

Code inspection applies `RLIMIT_AS` (address space), `RLIMIT_CPU`, core/file-size
caps before input reading and parsing, and a parent wall deadline. Spawn startup
can import entry-point modules before the worker target applies OS caps; the
parent wall deadline includes startup. The worker reports effective caps. Synthetic probes verify rejected oversized
address-space allocation and timeout cleanup. RSS is not measured by `RLIMIT_AS`.
These are parser process controls, not a malware sandbox or a network boundary.
Local verification uses a fresh Python 3.11.17 CPU virtual environment. On this
VM, `/tmp` is a small tmpfs with a per-user quota; repeated synthetic checkpoint
fixtures filled it. The final pytest invocation uses a fresh ignored
`artifacts/<study>/<run>/pytest_tmp` on disk, with one BLAS/OpenMP thread. Earlier
failed check logs remain preserved; only this task's temporary fixture folders
were removed.
`StaticPDFAnalyzer` and the existing `inspect`/`scan` feature extraction run in
the calling process; their byte/page/object checks do not bound allocations
inside libraries. Real-sample use requires the separately isolated LAB and
appropriate process wrapper, even when `scan --code-inspection` is selected.

Full action graphs, orphan objects, incremental revision history, additional
stream filters/encodings, JS lexical evidence after AST failure and exhaustive
embedded/XFA/font/image/RichMedia/URI/steganography exploit coverage remain future
work. `/JBIG2Decode` is an image filter; its presence does not identify JS.
Static syntax, action names, decoding failures and parser disagreement do not
prove maliciousness or actual execution. No new accuracy or speed is claimed.

## Existing offline commands

After these changes are committed and the worktree is clean, the existing
benchmark can record **synthetic warm-cache ingestion/resident inference** and
an isolated AST smoke check:

```bash
.venv/bin/python scripts/14_benchmark_static.py --samples 64 --repeats 3 --batch-size 32
```

That command creates a unique report run and appends the research log. It does
not benchmark real CIC PDFs, feature parsing or the full PDF-to-verdict path.
Once the user-established offline LAB conditions hold, the existing one-file
syntax-inspection command is:

```bash
.venv/bin/malpdf code-inspect /absolute/LAB/path/to/sample.pdf
```

The command defaults to one bounded worker and emits redacted JSON. It performs
no model fitting or held-out evaluation and is not an end-to-end latency study.
There is currently no CLI for a locked real-CIC B0/B1/B2/B3 latency/coverage
benchmark; that remains P3 work. `scripts/15_train_static_development.py` launches
Kaggle training and is outside this maintenance/offline benchmark scope.
